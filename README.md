# 花屿工坊 · 花艺布置设计与花材核算系统

浏览器内运行的婚礼/宴会花艺布置工具：参数化骨架建模、自动布花、实例化渲染、花材用量同源核算。数据全部存本地 IndexedDB，不依赖后端。

## 技术栈

- TypeScript + Vite
- three.js（InstancedMesh 实例化渲染）
- IndexedDB 本地持久化
- 零运行时 UI 框架，DOM 构造封装在 `src/core/dom.ts`

## 启动

```bash
pnpm install
pnpm dev
```

## 验证

```bash
pnpm build          # 类型检查 + 生产构建
pnpm test           # Node 冒烟测试（算法层与核算链路）
```

## 六个页面

| 页面 | 职责 |
| --- | --- |
| 场地档案 | 宴会厅层高、吊点承重、T 台与桌位，三维白模 |

| 结构搭建 | 拱门、圆环、花柱、花瀑吊架、主桌半球五种参数化铁艺件，花泥/网格区域编辑，吊点承重校验 |
| 插花编辑 | 抖动网格分层布花，防穿插，左键拔除、Shift/右键补花，枝长不足红色标记 |
| 现场预览 | 暖白/冷白/追光三种灯光，新人与摄像机位，背景屏遮挡分析 |

## 核心设计：一朵不差

渲染器与下单清单读的是同一份 `FlowerBuffer`（`src/three/dist.ts` 产出，IndexedDB 持久化）。
`buildChecksum`（`src/core/calc.ts`）在每次下单时比对画面有效花朵数与清单统计数，不一致直接报错，从数据源头杜绝「画面和清单对不上」。

## 渲染性能

- 按「花型模板 × 开放度桶」分桶为 InstancedMesh，六万朵花约 20~30 个 draw call
- 像素比上限 1.5，配合 OrbitControls 阻尼，1080p 下目标 45 帧以上
- 布花用固定 0.1m 格子的空间哈希做近邻查询，距离比较全部走平方，6 万朵秒级完成

## 已知边界

- 布花密度受物理容量约束：当目标朵数超过花头尺寸允许的铺排上限时，填充率会诚实下降并在编辑器给出提示，清单永远只按实际朵数核算
- 机位遮挡分析基于包围盒屏幕投影，是工程估算而非像素级渲染比对
